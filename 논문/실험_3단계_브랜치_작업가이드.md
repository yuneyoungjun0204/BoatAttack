## 1. 어느 브랜치로 가나
| | 브랜치 | 비고 |
|---|--------|------|
| **이동 대상** | **`two-USV-system`** | 논문 실험본. 결과(65%/15%)·보상·관측·차단망이 이 브랜치 기준 |
| 현재 작업 | `one-way_REFACTORING` | 논문 이후 진화(단동선 towing·클러스터 관측 등) → 논문과 다름 |

- **왜 two-USV-system?** ablation·다중시드는 논문의 방법/결과와 **동일 코드 기반**이어야 비교가 정합. `one-way_REFACTORING`에서 학습하면 관측·보상·기동이 달라 논문 수치와 직접 비교 불가.
- 확인: `git branch -a | grep two-USV-system`, 보상필드 정합은 [`논문_요약_정리.md`](논문_요약_정리.md) §대응 Git 브랜치 참조.

## 2. ★ 브랜치 이동 전 — 데이터 손실 방지 (필수)

> 배경 교훈: 과거 브랜치 전환 시 `git clean`이 **.gitignore된 대형 에셋(fbx/tga/Navy/Obi 등)을 삭제**한 참사가 있었음. 아래를 반드시 지킬 것.

### 2-1. 체크리스트 (이동 전)
1. **`git status`로 미커밋 확인.** 현재 untracked: `논문/` 폴더(.tex·MD·figures·hwp). 추적 파일 수정분이 있으면 함께 확인.
2. **`논문/` 폴더를 repo 밖에 백업.** 가장 확실한 안전장치:
   ```bash
   cp -r "c:/Users/ANSL/Desktop/BoatAttack/논문" "c:/Users/ANSL/Desktop/논문_backup_$(date +%Y%m%d)"
   ```
   - 이유: `논문/`은 untracked → 브랜치 전환 자체로는 안 지워지지만, 만약 `two-USV-system`에 동일 경로 추적파일이 있으면 **checkout이 거부/충돌**할 수 있음. 백업이 있으면 안심.
3. **미커밋 추적 변경은 커밋 또는 stash.**
   ```bash
   git stash push -u -m "one-way 작업 임시저장"   # -u: untracked 포함(논문/도 함께 보관됨)
   # 또는 커밋: git add -A && git commit -m "WIP: one-way 작업 저장"
   ```
   - ⚠ `stash -u`는 untracked(논문/)도 stash로 들어감 → 전환 후 `git stash pop`으로 복원. 헷갈리면 **2-2 방식(논문/만 별도 보관)** 권장.
4. **🚫 절대 금지: `git clean -fdx` / `-fd` / `-x`.** ignore된 fbx·tga·Navy·Obi·mov·Library 에셋이 통째로 삭제됨. 어떤 경우에도 실행하지 말 것.
5. **Unity 에디터 종료 후 전환.** 실행 중 전환은 `.meta`/`Library`/`Temp` 충돌·잠금 유발. 전환 후 Unity가 자동 재import(수 분 소요).
6. `One-Way_Towing/boatattack_sim`(별도 폴더/Python)은 **다른 작업트리** → BoatAttack 브랜치 전환과 무관. 영향 없음.

### 2-2. 가장 안전한 권장 절차 (논문/ 분리 보관)
```bash
cd "c:/Users/ANSL/Desktop/BoatAttack"
git status                                  # 1) 상태 확인
cp -r 논문 ../논문_backup_yyyymmdd           # 2) 논문 백업(repo 밖)
git add -A && git commit -m "WIP 저장"        # 3) 추적 변경 커밋 (논문/도 커밋해두면 전환 후에도 유지)
git switch two-USV-system                    # 4) 전환 (switch는 checkout보다 안전)
# 5) Unity로 프로젝트 열어 재import 완료 대기
```
- `git switch`는 브랜치 전용 명령이라 실수로 파일을 덮어쓸 위험이 `checkout`보다 적음.
- 전환 후 충돌 메시지가 뜨면 **강제(-f) 쓰지 말고** 어떤 파일이 막는지 확인 → 백업본과 대조.

### 2-3. 전환이 막힐 때
- "Your local changes would be overwritten" → 해당 파일 커밋/stash 후 재시도.
- "untracked working tree files would be overwritten" → 그 파일을 다른 이름으로 옮기고 전환(삭제 X).

## 3. two-USV-system에서 할 작업 (우선순위 순)

### 3-1. Fig.11 보상 스케일 규명 (가벼움 — 가장 먼저)
- 목적: 누적보상 y축 ≈2.4×10⁻⁵ 원인 규명·정정(리뷰 K).
- 작업:
  1. 기존 학습 로그 위치 확인: `results/<run-id>/` (TensorBoard event 파일).
  2. 스칼라 덤프 → `Environment/Cumulative Reward` 실제 범위 확인.
     ```python
     from tensorboard.backend.event_processing.event_accumulator import EventAccumulator
     ea = EventAccumulator("results/<run-id>"); ea.Reload()
     print(ea.Tags()["scalars"])
     vals=[s.value for s in ea.Scalars("Environment/Cumulative Reward")]
     print(min(vals), max(vals))
     ```
  3. 이벤트(±1) 포함 시 0.1~수 범위가 정상 → 현재 그래프가 비정상이면 **축 라벨/지표 오류**로 판단, 재플롯.
- 산출: 정정된 Fig.11 또는 "지표 정의 명확화" 문구.

### 3-2. MAPPO Ablation (중간)
- config 2벌 준비: `config/defense_boat_trainer.yaml` 복제.
  - `poca_defense.yaml`: `trainer_type: poca` (현행)
  - `ppo_defense.yaml`: `trainer_type: ppo` (나머지 하이퍼 동일)
- 동일 `max_steps`로 각각 학습 → 평가(3-4 프로토콜) → 포획률·붕괴율·학습안정성 비교.
- 핵심 메시지: 에이전트 **중도 이탈(포획완료/충돌/대형붕괴)** 빈발 환경에서 MA-POCA가 PPO 대비 우위인지 정량 입증.

### 3-3. 다중시드 통계 (무거움)
- 각 조건 5시드: `--seed 1..5`, `--run-id poca_s1..s5` / `ppo_s1..s5`.
- 시드별 지표 → 평균±표준편차, MA-POCA vs (PPO/LOS) t-test/Mann–Whitney(n=5).

### 3-4. 공통 평가 프로토콜
- 각 학습 모델(.onnx, 추론 모드) → **고정 40 에피소드 × 동일 적 포메이션 분포**.
- 지표: Capture / Penetration / Formation collapse rate (논문 정의 동일).
- LOS 게인(Kp,Kd) 스윕 1~2종 추가 평가 → "게인 민감도 낮음/baseline 합리적" 근거(리뷰 J).

## 4. 구현 디테일
- **config 위치**: `config/defense_boat_trainer.yaml` (트레이너·하이퍼). Stage·보상은 Inspector(`DefenseEnvController`/`DefenseRewardCalculator`).
- **학습**:
  ```bash
  mlagents-learn config/poca_defense.yaml --run-id=poca_s1 --seed 1
  mlagents-learn config/ppo_defense.yaml  --run-id=ppo_s1  --seed 1
  tensorboard --logdir=results
  ```
- **가속**: `time_scale 10`(20+는 Gerstner 파도 불안정), 씬 내 환경 인스턴스 복제로 병렬.
- **평가 스크립트**(신규 작성): 학습된 `.onnx`를 Inference로 로드 → 40에피 루프 → 종료사유 카운트(capture/breach/collapse) → CSV. 시드별 집계 → mean±std → 막대그래프(에러바).
- **재현성**: 보상·k·환경 값은 논문 표(`ICROS_2026.tex` Table 3) 기준 — formation α_f 0.002, approach 0.001, heading 0.0003, k_e 77/k_p 100, 활성간격 [20,120]m, 적스폰 1000m.
